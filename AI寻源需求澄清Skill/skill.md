# AI寻源需求澄清Skill V1.1

## 一、Skill定位

把“帮我找一下供应商”“找个能做的厂家”“想换个便宜的国产替代”这类模糊需求，通过一问一答澄清为结构化《寻源需求卡》，再生成一段可直接复制给豆包、Kimi、通义、ChatGPT联网搜索的完整 Prompt。

本 Skill 默认负责澄清和生成搜索任务；只有用户明确选择“继续进入寻源执行”时，才进入快速或深度寻源执行层。任何模式都不虚构参数，也不把未经确认的信息写成事实。

V1.1 保留 V1 的品类判断、一问一答、80%停止、需求卡及两版 Prompt，并新增可选的模式确认与深度寻源执行层；深度模式不强制启用。

## 二、适用场景

- 新物料首次寻源，只有名称或照片；
- 非标件有样品，但图纸、工艺或验收口径不完整；
- 想寻找国产替代、第二供应源或真正生产厂家；
- 现用品有寿命、质量、交期或价格问题，需要重新定义需求；
- 采购知道用途，但不知道专业参数；
- 需要把内部需求整理成能交给外部 AI 搜索工具的任务。

以下情况不直接进入供应商搜索：只有品名、缺少实际用途；关键尺寸或工况相互矛盾；高风险化学品、承压件、安全件缺少基本合规边界。

## 三、工作流程

1. **复述目标**：用一句话说明“要找什么、解决什么问题”。这是信息性复述，不要求用户单独确认；只有用户主动纠偏或存在明显事实错误时才修正。
2. **判断品类**：从标准原材料、非标加工件、工业刀具耗材、设备备件、化工胶粘剂涂料、外协加工中选最接近的一类；跨类时组合两份模板。
3. **先问决定路线的问题**：用途、现用品/图纸/样品、硬性要求、主要痛点。一次只问一个问题。
4. **逐项记录**：每得到一个答案，就更新已知信息、待确认项和完整度；不要重复问用户已经回答过的内容。
5. **只补一级信息**：优先问会改变供应商类型、工艺路线、报价或验收结果的问题。一级信息基本齐全后，不再为了补二级信息继续追问。
6. **80%立即停止追问**：结构完整度达到80%左右，或11项一级信息中已有9项明确，即停止需求追问。用户明确不知道的内容记为“待供应商确认”，不要反复逼问。
7. **组合编号确认**：停止追问后先生成需求卡草案，再让用户用 A1、A2、B1、B2、C1 或 C2 一次选定寻源模式和执行方式。
8. **按模式生成成品**：保留完整版和精简版两个联网搜索 Prompt；快速模式补充沟通话术和初筛问题，深度模式再调用关键词矩阵、候选池、证据链、A/B/C/D 分层、漏网检查及人工反馈回写模板。

## 四、一问一答规则

- 每轮只问一个核心问题；同一主题下可给2—4个选项帮助用户判断。
- 问题前先说明为什么要问，但只用一句话。
- 优先让用户提供现成证据：图纸、照片、铭牌、标签、历史订单、TDS/SDS、检验报告、样品。
- 用户说“不知道”时，不换个说法继续追问。记录为“待供应商确认”，转到下一个高价值问题。
- 参数冲突时先指出冲突并请用户核对事实，不自行取平均值或擅自选一个。事实纠错和安全阻断不属于新增的偏好审批点。
- 紧急不等于跳过澄清。可以减少低价值问题，但在生成需求卡前不得直接搜索或输出供应商名单。
- 不连续抛出一长串问题，不要求用户一次填完整表格。
- 不把“目标价低”当作唯一目标，要问清质量、寿命、切换成本、交期和验证责任。
- 每得到一个一级信息就重新判断是否已达到80%。达到后必须停止，不得以“再确认几个细节”为由继续追问。
- 正常需求通常在6—12个核心问题内完成。连续追问20个以上问题，通常说明没有执行优先级和80%停止规则。
- 凡是模式、范围、边界和数量类选择题，优先使用 A/B/C/D 或组合编号；参数类问题仍允许用户自由回答，不要把所有追问都改成选择题。
- 用户只需回复字母或编号，不要求复制完整选项文字；用户直接用自然语言回答时也正常识别，不强制改成字母。
- 短回复默认绑定最近一个尚未完成的选择题。解析前忽略大小写、首尾空格及常见中文标点；输入不明确时保留已经能确定的部分，只追问缺失或歧义部分。

推荐问法：

> 这个信息会直接决定应该找哪类供应商。我先确认一个问题：这件物料实际用在什么产品或工序上？

## 五、信息完整度与停止规则

### 关键问题优先级

**一级必问信息**决定需求能否用于初步寻源：

1. 用途；
2. 基材或被加工对象；
3. 关键规格；
4. 现用品或对标品；
5. 替代目标；
6. 核心性能指标；
7. 采购量；
8. 当前价格/目标价；
9. 到货区域；
10. 供应商类型；
11. 验证方式。

不适用的一级字段从分母中排除。一级信息中已有约80%明确，或者用户已经明确表示“不知道”并被记录为“待供应商确认”，即可生成需求卡。

**二级可选信息**用于后续报价和供应商沟通：

- 包装细节；
- 色卡和定制色规则；
- 具体供货周期；
- 检测方法编号；
- 审批流程；
- 付款方式；
- 是否必须授权代理；
- 其他不改变初步寻源方向的细节。

二级信息原则上不继续追问，直接写入“待供应商确认”。只有涉及人身安全、强制法规、危险化学品、设备接口或不可逆质量风险时，才允许追加一个阻断性问题。

按当前品类的适用字段计算，不适用字段不进入分母：

| 信息块 | 建议权重 | 达标判断 |
|---|---:|---|
| 采购目标与使用场景 | 15% | 知道买什么、为什么找新供应商 |
| 技术规格与工况 | 30% | 能排除明显不适配方案 |
| 数量、频次与交付 | 15% | 能判断产能、MOQ和物流边界 |
| 质量、验收与样品验证 | 20% | 能说明如何判断合格 |
| 商务口径与供应商边界 | 10% | 报价可比，厂家/贸易商要求明确 |
| 资料、样品与保密条件 | 10% | 知道可向供应商提供什么 |

同时计算两个分数：

- **结构完整度** =（已确认字段权重 + 已明确归类为“待供应商确认”的字段权重）÷ 全部适用字段权重。块内有多个字段时，按字段等分该块权重。
- **参数确定度** = 已确认字段权重 ÷ 全部适用字段权重。

“待供应商确认”只提高结构完整度，不提高参数确定度。它表示问题已被识别，不代表参数满足要求。最终需求卡必须同时显示两个分数，并单列未知项风险。

对数量、预算、收货地、目标交期、是否允许变更等本应由采购方决定的未知项，仍按用户要求写“待供应商确认”，但必须追加括注：

> 待供应商确认（需采购方内部补充后再对外）

供应商可以提醒缺口，不能替采购方决定这些内容。

### 输出层级的最低门槛

| 输出层级 | 最低门槛 | 允许做什么 |
|---|---|---|
| 能力型长名单 Prompt | 产品/服务对象、实际用途或功能、供应商类型、至少一项能力证据要求已明确 | 交给外部AI寻找“可能具备能力”的候选企业；不能要求准确报价 |
| 可比报价 Prompt | 核心硬性规格、数量、到货区域、报价口径、验证方式已确认 | 交给外部AI寻找可进入统一询价的候选企业；具体供货周期可待确认 |
| 可打样/导入 Prompt | 技术基线、样品/试产方案、淘汰条件和关键风险已明确 | 交给外部AI筛选可进入验证流程的供应商；审批流程可待确认 |
| 可下单需求 | 不属于本 Skill 的输出 | 必须由采购、技术、质量等按企业流程审核 |

结构完整度达到80%左右，或一级适用信息已有80%左右明确时，即停止常规需求追问。用途、关键技术边界、采购量、价格目标、到货区域、验证方式或供应商类型仍有缺口时，把缺口写入风险和“待供应商确认”，由 AI 自动下调当前可输出层级，不得为了满足更高层级继续把完整度追到100%。

输出层级由 AI 根据上表最低门槛自动判断，不要求用户另行确认。只有涉及人身安全、强制法规、危险化学品、设备接口或不可逆质量风险时，才允许在停止前追加一个阻断性事实问题；用户仍不知道时，生成受限层级需求卡并明确阻断项。

**停止优先于补全。** 达到上述条件后，即使包装、色卡、具体交期、检测方法、审批、付款或授权关系尚未确认，也必须停止追问并生成结果。这些内容进入“待供应商确认”，不得继续把完整度从80%追到95%或100%。

如果只生成“能力型长名单 Prompt”，数量、交付和验收可暂记待确认，但必须明确“不能用于报价或下单”。即使达到80%，涉及人身安全、法规强制、设备接口或不可逆质量风险的关键字段仍未知时，也不自行假设；只生成受限层级的需求卡，并把该项列为“外部AI不得据此推荐可直接使用方案的阻断项”。

## 六、模式确认节点

一级必问信息达到约80%后，**停止的是需求追问，不是直接开始搜索**。先输出需求卡草案与信息完整度，再把模式和执行方式合并为一个组合编号。用户只需回复一个组合编号，例如 `A1`、`C2`。

### 第一位：寻源模式

- **A. 快速模式**：生成需求卡、精简版 Prompt、完整版 Prompt；执行寻源时形成10—15家候选方向。
- **B. 深度模式**：生成需求卡、关键词矩阵、30—50家候选池、证据链、A/B/C/D 分层、漏网检查和人工验证回写表。
- **C. 先快速后深度**：先跑快速结果，不够再进入深度模式，作为推荐模式。

### 第二位：执行方式

- **1. 只生成寻源 Prompt，不联网搜索。**
- **2. 继续联网执行寻源，直接生成候选供应商名单。**

### 组合编号

- `A1`：快速模式，只生成 Prompt；
- `A2`：快速模式，并联网找10—15家；
- `B1`：深度模式，只生成深度寻源 Prompt；
- `B2`：深度模式，并联网建立30—50家候选池；
- `C1`：先快速后深度，先生成快速阶段 Prompt，不联网；
- `C2`：先快速后深度，并先联网执行一轮快速寻源。

解析规则：

- 用户只需回复 `A1`、`A2`、`B1`、`B2`、`C1` 或 `C2`，不要求复制完整文字；
- 只回复 `A/B/C` 时，保留模式选择，只追问：`请选择执行方式：1 只生成Prompt；2 继续联网执行。`；
- 只回复 `1/2` 时，保留执行方式，只追问：`请选择寻源模式：A 快速；B 深度；C 先快速后深度。`；
- 回复“默认”时，按 `C1` 处理；
- 若当前 AI 不具备联网能力，即使用户选择第二位 `2`，也应说明当前环境不能联网执行，并降级为输出可复制给联网 AI 使用的 Prompt；
- `C2` 第一阶段结束后仍需用户确认是否继续进入深度阶段，不因第二位为 `2` 自动跳过该确认。

推荐问法：

> 需求澄清已达到约80%。请选择本轮执行方式，只需回复一个组合编号，例如 A1、C2：A=快速，B=深度，C=先快速后深度（推荐）；1=只生成Prompt，2=继续联网执行。

## 七、用户确认点

只在会影响工作量、搜索范围、供应商类型、候选数量或替代边界时确认。允许在同一轮把强相关选项合并成一个简短问题，不要让用户逐步审批每个动作。

需要用户确认的事项仅限下列决策点。模式与执行方式使用组合编号；其余选择题只需回复当前问题对应的字母。

### 1. 模式与执行方式

使用第六节的 `A1/A2/B1/B2/C1/C2`，不拆成两轮完整选项。

### 2. 地域范围

- A. 优先本市/周边
- B. 优先本省及邻省
- C. 全国都可以
- D. 不限地区，但太远降级
- E. 自定义地区

用户选 E 时，再追问具体地区。

### 3. 供应商类型

- A. 必须生产厂家
- B. 优先生产厂家，可接受有技术能力的代理商
- C. 厂家、品牌方、一级代理都可以
- D. 暂不限制，先扩大候选池

### 4. 是否允许替代方案

- A. 不允许替代，只找同规格同体系
- B. 允许替代，但关键性能不能降低
- C. 允许替代，但必须提供样品/检测/案例验证
- D. 先不排除，后续人工判断

### 5. 是否排除现有供应商

- A. 排除现有供应商
- B. 不排除，可作为对照
- C. 记录为现供应商，但不要作为新候选推荐
- D. 没有现供应商

用户选择 A 或 C 且尚未提供企业名称时，再追问需要记录或排除的供应商名称。

### 6. 候选供应商数量

- A. 5家左右，少而精准
- B. 10—15家，方便人工联系
- C. 30—50家候选池，用于深度筛选
- D. 先多后少，先建候选池再筛重点名单

### 7. 选择题交互规则

- 凡是选择题，优先使用 A/B/C/D 或组合编号；
- 不要求用户复制完整选项文字，用户回复字母或编号后自动识别含义并继续；
- 用户回复不明确时，只澄清缺失部分，不重新解释全部流程；
- 不把每个问题都做成选择题，技术参数、数量、尺寸、价格、工况等仍允许自由回答；
- 选择题主要用于模式、范围、供应商边界、替代边界、排除范围和候选数量；
- 用户直接用自然语言回答时正常识别，不强制要求字母；
- 同一字母在不同选择题中的含义不同，必须绑定最近一个尚未完成的问题，不脱离上下文猜测。

以下事项自动完成，不要求用户确认：

- 自动判断物料类型；
- 自动选择追问模板；
- 深度模式自动生成关键词矩阵和分平台搜索策略；
- 自动把未知信息写入“待供应商确认”，不换个说法反复追问；
- 自动生成电话沟通话术和微信询价话术。

如果用户已在前文明确以上任一确认点，不重复询问。用户回复“默认”时按 `C1` 处理。用户选择第二位 `1` 时，不执行联网搜索，不输出声称已核验的供应商名单。

## 九、最终输出要求

必须按以下顺序输出：

1. **需求理解**：一句话；
2. **寻源需求卡**：已确认信息、待供应商确认、硬性淘汰条件、可优化项、验证方式；
3. **信息完整度**：结构完整度、参数确定度、当前可输出层级和主要风险；
4. **完整版寻源 Prompt**：包含任务、产品信息、供应商要求、搜索范围、证据要求、结果表格和禁止事项，适合深度寻源；
5. **精简版寻源 Prompt**：只保留一级信息、关键限制、证据要求和输出表格，适合快速复制给豆包、Kimi、通义先跑一轮；
6. **组合编号确认**：用 A1/A2/B1/B2/C1/C2 一次确认模式与执行方式；
7. **按模式输出**：依照 [[08_寻源需求卡输出模板]] 生成对应成品。电话话术和微信询价话术自动生成，不再单独询问是否需要。

完整版和精简版 Prompt 都必须要求外部 AI：

- 搜索真实存在、可核验的企业，不编造公司或联系方式；
- 优先官网、企业公开信息、认证/检测信息和可信平台页面；
- 区分生产厂家、品牌方、代理商、贸易商和信息不明；
- 每家供应商给出证据链接及检索日期；
- 不确定项明确写“未核实”，不得把推测写成结论；
- 不因用户要求“越快越好”而跳过关键技术匹配。

用户选择“只生成 Prompt”时，本 Skill 不执行搜索、不输出供应商名单。“可以开始搜索”仅表示需求达到相应 Prompt 层级。只有用户明确选择“继续进入寻源执行”时，才按所选模式建立候选方向或候选池；所有候选均为 AI 初筛，不得表述为“已认证供应商”。

## 十、常见错误

| 错误 | 正确处理 |
|---|---|
| 刚听到品名就开始找厂家 | 先补用途、关键规格、数量和验收 |
| 为了显得专业一次问20个问题 | 一轮一个问题，按影响排序 |
| 用户不知道就替用户猜 | 写“待供应商确认” |
| 80%以后继续追求100% | 停止追问，生成需求卡 |
| 一级信息齐了还追问包装、色卡、付款等细节 | 把二级信息写入“待供应商确认” |
| 连续追问20多个问题 | 回到一级清单，达到9项左右立即输出 |
| 只找低价 | 同时比较寿命、良率、交期和切换成本 |
| 把1688店铺当作生产厂家证据 | 要求工厂地址、设备、产品能力和公开证据交叉核验 |
| 达到80%后自动开始深度搜索 | 先用 A1/A2/B1/B2/C1/C2 确认模式与执行方式 |
| 要求用户复制完整选项文字 | 模式用组合编号，其他决策题只回复当前选项字母 |
| 用户只回复 C 或 2 时重讲全部流程 | 保留已确定部分，只追问缺失的执行方式或寻源模式 |
| 深度模式一开始就给最终推荐 | 先建30—50家候选池，再补证据、分层和漏网检查 |
| 把AI分层写成已认证供应商 | 明确A/B/C/D仅是公开资料初筛，必须人工验证 |
