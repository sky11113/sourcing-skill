# 01 通用采购追问框架

## 一、先判断用户真正要的结果

如果用户只说“帮我找供应商”，且没有说明想要名单、报价、样品还是合格供应商，首轮先问：

> 这次寻源最终想拿到什么结果：候选厂家名单、可比报价、样品，还是可以导入的合格供应商？

如果用户已经明确说“找厂家名单”“拿报价”或“做样品”，不要重复问结果类型，直接进入品类中最能决定技术路线的问题。结果类型决定追问深度：只要名单，可以做到“能力型长名单”；要报价、样品或导入，必须补齐相应最低门槛。

## 二、通用关键字段

| 优先级 | 模块 | 关键字段 | 实战问法 |
|---|---|---|---|
| 一级 | 使用场景 | 具体用途、产品或工序 | 它具体用在哪里，主要发挥什么作用？ |
| 一级 | 基材/对象 | 接触基材或被加工对象 | 它接触、粘接或加工什么材料？ |
| 一级 | 核心规格 | 尺寸、材质、性能、接口 | 哪些参数错一点就不能用？ |
| 一级 | 现用品 | 型号、品牌、图号、样品或对标品 | 现在用的是什么，有没有型号或样品？ |
| 一级 | 替代目标 | 新增、替代、降本、保交期、质量改善 | 这次寻源最想解决哪个问题？ |
| 一级 | 核心性能 | 外观、尺寸、性能、寿命、可靠性 | 哪几项性能不能低于现用品？ |
| 一级 | 采购量 | 首批量、月/年用量 | 稳定后每月或每年大概需要多少？ |
| 一级 | 价格 | 当前价格、目标价格、比较口径 | 现价和希望控制的目标价是多少？ |
| 一级 | 到货区域 | 主要收货城市或服务范围 | 通常送到哪个区域？ |
| 一级 | 供应商类型 | 厂家、品牌方、代理商、贸易商 | 必须生产厂家，还是品牌方或代理也可以？ |
| 一级 | 验证方式 | 样品、试产、检测、审核 | 候选产品最终怎么验证合格？ |
| 二级 | 包装与交期 | 包装、色卡、具体供货周期、库存 | 由供应商首轮确认，非阻断时不继续追问 |
| 二级 | 检测与审批 | 检测方法、审批流程、授权关系 | 由供应商提供资料或采购方后续补充 |
| 二级 | 商务与保密 | 付款、账期、NDA、报价有效期 | 进入询价或导入阶段再确认 |

## 三、追问排序

1. 先问用途和基材，确认物料路线；
2. 再问关键规格、现用品、替代目标和核心性能；
3. 再问采购量、当前价/目标价、到货区域、供应商类型和验证方式；
4. 每问完一项就检查一级信息是否已达到约80%；
5. 达到约80%后立即停止。包装、色卡、具体供货周期、检测方法、审批、付款和授权关系等二级信息写入“待供应商确认”。

若用户只回答一句话，从以下问题开始：

> 先不谈厂家，你能说一下这个物料实际用在什么地方、现在最想解决什么问题吗？

## 四、已知、未知和冲突的记录方式

- **已确认**：用户明确回答，或有图纸、铭牌、报告支持。
- **待供应商确认**：用户不知道，但供应商可以通过选型、测绘、试样或资料核对确认。
- **待采购方确认**：涉及采购政策、预算、审批、保密、收货等，供应商不能替采购方决定。
- **信息冲突**：两个来源不一致，必须列出两种说法和来源，不擅自合并。

主 Skill 的固定措辞仍使用“待供应商确认”；若实际责任在采购方，可在备注里写“需采购方内部确认后再给供应商”。

## 五、80%后的动作

一级适用信息已有约80%明确，或11项一级信息中已有9项明确后，不要继续像审表一样追问。直接输出：

- 哪些信息已经足够用于搜索；
- 哪些信息必须由供应商首轮回复；
- 哪些供应商只能进入长名单、暂不能报价；
- 当前参数确定度；
- 下一步是把 Prompt 交给外部AI做资料筛选、样品验证还是现场审核准备。

不要为了得到以下信息继续追问：包装、色卡、精确交期、检测方法编号、审批流程、付款方式、授权代理细节。除非其中某项会造成安全、合规或不可逆质量风险，否则统一列为二级待确认项。

## 六、通用淘汰条件示例

- 无法说明实际生产地点或关键工序由谁完成；
- 报价口径不完整，拒绝说明税、运费、MOQ；
- 关键参数只口头承诺，不愿提供资料或样品验证；
- 产品与需求明显不匹配，却承诺“都能做”；
- 关键合规文件过期、适用产品不一致或无法核验；
- 涉及图纸和样品时拒绝基本保密要求。
